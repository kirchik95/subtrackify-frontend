### 3.9 Async thunk boilerplate

Every `createAsyncThunk` in `src/features/{auth,subscriptions,profile,analytics}/store/actions.ts` repeats the same try/catch/`rejectWithValue` shape:

```13:32:src/features/auth/store/actions.ts
export const login = createAsyncThunk(
  'auth/login',
  async (
    { rememberMe, ...credentials }: LoginCredentials & { rememberMe?: boolean },
    { rejectWithValue }
  ) => {
    try {
      const response = await authApi.login(credentials, rememberMe);

      if (!response.success || !response.data) {
        return rejectWithValue(response.error || 'Login failed');
      }

      return response.data;
    } catch (error) {
      const apiError = error as { success: false; error: string };
      return rejectWithValue(apiError.error || 'Login failed');
    }
  }
);
```

Fifteen thunks share that exact body shape (only the API call and the fallback string differ). **Recommendation.** Extract a helper:

```ts
function apiThunk<TArg, TData>(
  type: string,
  fn: (arg: TArg) => Promise<ApiResponse<TData>>,
  fallback: string
) {
  return createAsyncThunk<TData, TArg>(type, async (arg, { rejectWithValue }) => {
    try {
      const r = await fn(arg);
      if (!r.success || !r.data) return rejectWithValue(r.error || fallback);
      return r.data;
    } catch (e) {
      return rejectWithValue((e as { error?: string }).error || fallback);
    }
  });
}
```

Cuts the four `actions.ts` files roughly in half and centralises error handling.

**Recommendation.** Drop the three unused `@fontsource-variable/*` imports from `main.tsx` _and_ the corresponding entries from `package.json`. Update `docs/stack.md` to mention only the fonts that are actually used.

### 5.2 Direct token-reading bypassing `apiClient`

```86:86:src/common/api/profile.ts
    const token = localStorage.getItem('auth_token') || sessionStorage.getItem('auth_token');
```

`exportCsv` re-implements the token lookup that `apiClient.getAccessToken()` already does — including hard-coding the storage key (`'auth_token'`) which is otherwise encapsulated as `ApiClient.ACCESS_TOKEN_KEY`. If that key ever changes, this site silently breaks. **Recommendation.** Read the token via `apiClient.getAccessToken()`, or move the `fetch` into `apiClient` so the auth header is auto-attached.

### 5.3 depcheck false positives — leave alone

`depcheck` reports `tailwindcss`, `tw-animate-css`, `prettier`, `@ianvs/prettier-plugin-sort-imports`, and `lint-staged` as unused. They are all referenced through non-JS entry points (`src/assets/styles/index.css`, `prettier.config.js`, `lint-staged.config.js`, `vite.config.ts`). Keep them.

## 6. Suggested cleanup order

If a follow-up PR wants to act on this audit, the cheapest wins first:

1. **Quick deletes** (no behaviour change): `update_paper.js`, `src/types/global.d.ts`, `src/common/entities/index.ts`, `src/common/utils/localStorage.ts`, the seven unused shadcn primitives, the three unused fontsource imports, `apiClient.setToken`, `subscriptionsApi.getById`, `profileApi.removeAvatar`, `subscriptionActions.{addSubscription,removeSubscription,updateSubscription}`, `authActions.clearError`, `SubscriptionFrequency`, the unused selectors in `auth/store/selectors.ts`. **Estimated impact:** ~700 lines of source removed, several MB off the font payload.
2. **Strip debug logs** in `useAuthInit.ts`. Wire (or remove) the placeholder `Log out` command. Fix the `/settings` header link. **Behavioural impact:** non-trivial — token logging is a real leak.
3. **Extract shared utilities** for `formatDate` / `formatBillingCycle`, `getColorFromName`, the async-thunk wrapper, and the fullscreen spinner.
4. **Consolidate Auth-screen UI** (`GoogleLoginButton`, `PasswordField`) — this is where the largest verbatim duplication lives.
5. **Unify the subscription form** between Add and Edit dialogs. Highest value but also the most invasive change; do it last.

Each step is independently mergeable and independently verifiable.
